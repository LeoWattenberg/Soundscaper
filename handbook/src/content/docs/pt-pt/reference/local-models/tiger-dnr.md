## Finalidade e caso de utilização {#purpose-and-use-case}

Separar uma faixa de áudio mista em diálogos, música e efeitos.

## Disponibilidade atual {#current-availability}

As compilações para computador podem transferir e autenticar o motor onnxruntime-node 1.29.0 necessário para macOS arm64, Linux x64, Linux arm64, Windows x64, Windows arm64. Instale este modelo e o respetivo runtime necessário através do Gestor de modelos e execute a tarefa localmente. Estes são os destinos de compilação suportados; consulte o relatório de testes noturnos para ver os resultados de um pacote e computador específicos.

## Utilize este modelo {#use-this-model}

Abra **Ferramentas → Processamento Local Avançado → Separação de Fontes** numa plataforma com o tempo de execução nativo necessário. A assistência local funciona no editor de desktop.

1. Selecione o áudio misto a separar.
2. Instale o TIGER através do Gestor de Modelos e, em seguida, execute a separação de fontes.
3. Ouça cada proposta de stem antes de adicionar os resultados desejados ao projeto.

## Transferência e requisitos {#download-and-requirements}

Identidade do modelo: `tiger-dnr`, versão **1.0.0**.

Tamanho aproximado da transferência do artefacto do modelo: **28.25 MiB**. O runtime necessário é acrescentado à primeira transferência se ainda não estiver instalado. Memória mínima do sistema: **4 GiB**. Este requisito do catálogo refere-se à memória total, não à memória livre no momento. A inferência também precisa de memória livre suficiente e a instalação precisa de espaço de trabalho; a memória não garante velocidade.

Plataformas publicadas: macOS arm64, Linux x64, Linux arm64, Windows x64, Windows arm64. Também é necessário um runtime correspondente transferível.

No Windows, instale o [Microsoft Visual C++ v14 Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170) suportado mais recente que corresponda à aplicação para computador: **x64** para uma compilação x64 ou **ARM64** para uma compilação ARM64. Os motores nativos ONNX e Sherpa precisam destas bibliotecas; as transferências do modelo e do runtime não as incluem. O Visual Studio não é necessário para utilizar a aplicação.

Ferramentas → Gestor de modelos transfere os artefactos publicados do modelo e o runtime necessário na primeira instalação e verifica os resumos SHA-256 registados. O processamento utiliza os ficheiros instalados localmente. Abra Armazenamento e verificação no Gestor de modelos para consultar avisos, reparar uma instalação ou alterar a localização de armazenamento.
