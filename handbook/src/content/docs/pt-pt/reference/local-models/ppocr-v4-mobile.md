## Finalidade e caso de utilização {#purpose-and-use-case}

Ler texto visível de quadros de vídeo amostrados para revisão e indexação.

## Disponibilidade atual {#current-availability}

As compilações para computador podem transferir e autenticar o motor onnxruntime-node 1.29.0 necessário para macOS arm64, Linux arm64, Linux x64, Windows arm64, Windows x64. Instale este modelo e o respetivo runtime necessário através do Gestor de modelos e execute a tarefa localmente. Estes são os destinos de compilação suportados; consulte o relatório de testes noturnos para ver os resultados de um pacote e computador específicos. A compilação para computador não disponibiliza um motor transferível para macOS x64, apesar de os pesos do modelo estarem listados para essa plataforma.

## Utilize este modelo {#use-this-model}

Abra **Framescaper: Ferramentas → Pesquisa → Indexar Vídeo, ou Ferramentas → Processamento Local Avançado → Reconhecimento Ótico de Caracteres** numa plataforma com o tempo de execução nativo necessário. A assistência local funciona no editor de ambiente de trabalho.

1. Selecione o vídeo que contém texto legível no ecrã.
2. Instale o PP-OCRv4 móvel através do Gestor de Modelos. É um passo opcional do Indexar Vídeo, que também utiliza o SigLIP2.
3. Execute localmente e reveja o texto reconhecido e as suas localizações de quadro antes de aceitar os resultados.

## Transferência e requisitos {#download-and-requirements}

Identidade do modelo: `ppocr-v4-mobile`, versão **4.0.0**.

Tamanho aproximado da transferência do artefacto do modelo: **15.46 MiB**. O runtime necessário é acrescentado à primeira transferência se ainda não estiver instalado. Memória mínima do sistema: **2 GiB**. Este requisito do catálogo refere-se à memória total, não à memória livre no momento. A inferência também precisa de memória livre suficiente e a instalação precisa de espaço de trabalho; a memória não garante velocidade.

Plataformas publicadas: macOS arm64, macOS x64, Linux arm64, Linux x64, Windows arm64, Windows x64. Também é necessário um runtime correspondente transferível.

No Windows, instale o [Microsoft Visual C++ v14 Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170) suportado mais recente que corresponda à aplicação para computador: **x64** para uma compilação x64 ou **ARM64** para uma compilação ARM64. Os motores nativos ONNX e Sherpa precisam destas bibliotecas; as transferências do modelo e do runtime não as incluem. O Visual Studio não é necessário para utilizar a aplicação.

Ferramentas → Gestor de modelos transfere os artefactos publicados do modelo e o runtime necessário na primeira instalação e verifica os resumos SHA-256 registados. O processamento utiliza os ficheiros instalados localmente. Abra Armazenamento e verificação no Gestor de modelos para consultar avisos, reparar uma instalação ou alterar a localização de armazenamento.

Caso: `ppocr-recognized-text`; operação: `optical-character-recognition`.

Entrada: Quadros com as palavras de alto contraste “TESTE DE MODELO LOCAL”, com temporização de quadro de origem explícita.

As regiões de texto devem conter texto reconhecido não vazio, temporização de quadro de origem válida, pontuações de confiança finitas e caixas delimitadoras.

O pacote nightly-with-tests transfere os artefactos reais do modelo e runtimes verificados antes da inferência. A ausência no catálogo de um modelo necessário faz falhar o respetivo caso. A ausência de motores nativos provoca falhas nas plataformas suportadas pelo catálogo. Estas verificações dispendiosas são executadas separadamente da suite normal do navegador. Uma execução bem-sucedida confirma o funcionamento básico do modelo e uma estrutura de saída utilizável; não comprova a qualidade percetiva nem a precisão na sua gravação.

## Revisão do resultado {#review-the-result}

- Texto pequeno, desfocado, rodado, estilizado ou parcialmente oculto pode ser perdido ou lido incorretamente.
- O teste embalado requer regiões de texto, portanto, o detector, o modelo de orientação e o reconhecedor executam todos. Não exige uma correspondência caracter-a-caracter.
