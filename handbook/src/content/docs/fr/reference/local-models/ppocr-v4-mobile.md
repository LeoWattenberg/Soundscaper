## Objectif et cas d’utilisation {#purpose-and-use-case}

Lisez le texte visible à partir d'images extraites de vidéos pour révision et indexation.

## Disponibilité actuelle {#current-availability}

Les versions de bureau peuvent télécharger et vérifier le moteur onnxruntime-node 1.29.0 requis pour macOS arm64, Linux arm64, Linux x64, Windows arm64, Windows x64. Installez ce modèle et son runtime requis via le Gestionnaire de modèles, puis exécutez la tâche localement. Ce sont les cibles de construction prises en charge ; consultez le rapport de test nocturne pour les résultats d’un package et d’une machine spécifiques. Il n’existe pas de moteur téléchargeable pour macOS x64, bien que les poids du modèle soient répertoriés pour cette plateforme.

## Utilisez ce modèle {#use-this-model}

Ouvrez **Framescaper : Outils → Recherche → Indexer la vidéo** ou **Outils → Traitement local avancé → Reconnaissance optique de caractères** sur une plateforme avec le runtime natif requis. L'assistance locale s'exécute dans l'éditeur de bureau.

1. Sélectionnez une vidéo contenant du texte lisible à l'écran.
2. Installez PP-OCRv4 mobile via Gérer les modèles. C'est une étape optionnelle de l'Indexation de vidéo, qui utilise également SigLIP2.
3. Exécutez-le localement et révisez le texte reconnu et ses emplacements de trame avant d'accepter les résultats.

## Téléchargement et exigences {#download-and-requirements}

Identité du modèle : `ppocr-v4-mobile`, version **4.0.0**.

Taille approximative du téléchargement de l’artefact du modèle : **15.46 MiB**. Le runtime requis s’ajoute au premier téléchargement s’il n’est pas déjà installé. Mémoire système minimale : **2 GiB**. Cette exigence du catalogue concerne la mémoire totale, et non la mémoire libre actuelle. L’inférence nécessite également suffisamment de mémoire libre et l’installation de l’espace disque ; la mémoire ne garantit pas la vitesse.

Plateformes publiées : macOS arm64, macOS x64, Linux arm64, Linux x64, Windows arm64, Windows x64. Un runtime téléchargeable correspondant est également requis.

Sous Windows, installez le dernier [Microsoft Visual C++ v14 Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170) pris en charge et correspondant à l’application de bureau : **x64** pour une version x64 ou **ARM64** pour une version ARM64. Les moteurs ONNX et Sherpa natifs nécessitent ces bibliothèques ; les téléchargements du modèle et du runtime ne les incluent pas. Visual Studio lui-même n’est pas nécessaire pour utiliser l’application.

Outils → Gestionnaire de modèles télécharge les artefacts publiés du modèle et le runtime requis lors de la première installation, puis vérifie leurs empreintes SHA-256 enregistrées. Le traitement utilise les fichiers installés localement. Ouvrez Stockage et vérification dans le Gestionnaire de modèles pour consulter les avis, réparer une installation ou modifier l’emplacement de stockage.

<details id="what-the-packaged-test-checks">
<summary>Ce que vérifie le test de bureau</summary>

Cas : `ppocr-recognized-text` ; opération : `optical-character-recognition`.

Entrée : Images contenant les mots à fort contraste « TEST DU MODÈLE LOCAL », avec un minutage explicite de la source.

Les régions de texte doivent contenir du texte reconnu non vide, un minutage de trame source valide, des scores de confiance finis et des boîtes délimitées.

Le package nightly-with-tests télécharge les vrais artefacts du modèle et les runtimes vérifiés avant l’inférence. Un modèle requis absent du catalogue fait échouer son cas. L’absence de moteurs natifs entraîne un échec sur les plateformes prises en charge par le catalogue. Ces vérifications coûteuses s’exécutent séparément de la suite de navigateurs normale. Une exécution réussie confirme le fonctionnement de base du modèle et une structure de sortie utilisable ; elle n’établit ni la qualité perceptuelle ni la précision sur votre enregistrement.

## Révisez le résultat {#review-the-result}

- Le texte petit, flou, incliné, stylisé ou partiellement caché peut être manqué ou mal lu.
- Le test empaqueté nécessite des régions de texte, donc le détecteur, le modèle d'orientation et le reconnaisseur s'exécutent tous. Il ne demande pas de correspondance caractère par caractère.
