Créez des représentations numériques locales des passages de transcription et des requêtes de recherche pour la recherche sémantique.

## Disponibilité actuelle {#current-availability}

Les builds de bureau incluent le moteur onnxruntime-node 1.29.0 requis pour macOS arm64, Linux arm64, Linux x64, Windows arm64 et Windows x64. Installez les poids de ce modèle via le Gestionnaire de modèles, puis exécutez la tâche localement. Ce sont les cibles de build prises en charge ; consultez le rapport de test nocturne pour les résultats sur un package et une machine spécifiques. Le build de bureau ne package pas ce moteur pour macOS x64, même si les poids du modèle sont répertoriés pour ces plateformes.

## Utilisez ce modèle {#use-this-model}

Ouvrez **Outils → Recherche → Indexer la transcription, puis Outils → Recherche → Recherche indexée** sur une plateforme avec le runtime natif requis. L'assistance locale s'exécute dans l'éditeur de bureau.

1. Créez ou importez une transcription, puis installez Nomic Embed Text via Gérer les modèles.
2. Exécutez Indexer la transcription pour préparer le texte à la recherche sémantique.
3. Utilisez la Recherche indexée et examinez les passages correspondants dans leur contexte. Le traitement local avancé expose également l'opération d'encapsulation.

## Téléchargement et exigences {#download-and-requirements}

Identité du modèle : `nomic-embed-text-v1.5`, version **1.5.0**.

Taille de téléchargement approximative : **131,62 Mo**. Mémoire système minimale : **4 Go**. Cette exigence de catalogue fait référence à la mémoire totale, et non à la mémoire libre actuelle. L'inférence nécessite également une mémoire libre suffisante, et l'installation nécessite de l'espace de travail ; la mémoire n'est pas une garantie de vitesse.

Plateformes publiées : macOS arm64, macOS x64, Linux arm64, Linux x64, Windows arm64, Windows x64. Un runtime empaqueté correspondant est également requis.

Sous Windows, installez la dernière version prise en charge de [Microsoft Visual C++ v14 Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170) correspondant à l'application de bureau : **x64** pour un build x64 ou **ARM64** pour un build ARM64. Les moteurs natifs ONNX et Sherpa nécessitent ces bibliothèques ; les téléchargements de modèles ne les incluent pas. Visual Studio lui-même n'est pas requis pour utiliser l'application.

Outils → Gestionnaire de modèles télécharge les artefacts publiés et vérifie leurs hashes SHA-256 enregistrés. Le traitement utilise les fichiers installés localement. ## Ce que le test empaqueté vérifie {#what-the-packaged-test-checks}

Cas : `nomic-text-embedding` ; opération : `text-embedding`.

Entrée : Un court passage de texte non vide fourni au véritable tokeniseur et au réseau d'encapsulation.

Les vecteurs d'encapsulation doivent avoir les dimensions attendues et contenir des valeurs finies, non nulles et non constantes.

Le package nightly-with-tests télécharge les véritables artefacts de modèle et demande une inférence via le runtime empaqueté. Un modèle requis manquant du catalogue fait échouer son cas. Les moteurs natifs manquants font échouer les plateformes prises en charge par le catalogue. Ces contrôles coûteux s'exécutent séparément de la suite de navigateurs normale. Une exécution réussie confirme l'exécution de base du modèle et la structure de sortie utilisable ; elle n'établit pas la qualité perceptuelle ou la précision sur votre enregistrement.

## Examinez le résultat {#review-the-result}

- Les encapsulations sont des données de recherche numériques, et non une transcription réécrite ou une réponse générée.
- Les passages connexes peuvent se classer différemment entre les exécutions ou les enregistrements. Les vecteurs finis et non constants valident l'exécution, et non la pertinence de chaque correspondance.
