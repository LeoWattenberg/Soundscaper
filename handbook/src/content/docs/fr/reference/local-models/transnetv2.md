Détectez les transitions de plans dans une vidéo en utilisant le chemin du modèle local précis.

## Disponibilité actuelle {#current-availability}

Les builds de bureau incluent le moteur onnxruntime-node 1.29.0 requis pour macOS arm64, Linux x64, Linux arm64, Windows x64 et Windows arm64. Installez les poids de ce modèle via le Gestionnaire de modèles, puis exécutez sa tâche localement. Ce sont les cibles de build prises en charge ; consultez le rapport de test nocturne pour les résultats sur un package et une machine spécifiques.

## Utilisez ce modèle {#use-this-model}

Ouvrez **Framescaper : Outils → Traitement local avancé → Détection de plans** sur une plateforme dotée du runtime natif requis. L'assistance locale s'exécute dans l'éditeur de bureau.

1. Sélectionnez une vidéo dans Framescaper.
2. Installez TransNetV2 via le Gestionnaire de modèles et choisissez la détection de plans basée sur le modèle.
3. Examinez les limites de plan proposées avant d'ajouter des annotations ou de les utiliser pour planifier des éditions.

## Téléchargement et exigences {#download-and-requirements}

Identité du modèle : `transnetv2`, version **1.0.0**.

Taille de téléchargement approximative : **29,81 Mo**. Mémoire système minimale : **2 Go**. Cette exigence de catalogue fait référence à la mémoire totale, et non à la mémoire libre actuelle. L'inférence nécessite également une mémoire libre suffisante, et l'installation nécessite de l'espace de travail ; la mémoire n'est pas une garantie de vitesse.

Plateformes publiées : macOS arm64, Linux x64, Linux arm64, Windows x64, Windows arm64. Un runtime empaqueté correspondant est également requis.

Sous Windows, installez la dernière version prise en charge de [Microsoft Visual C++ v14 Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170) correspondant à l'application de bureau : **x64** pour un build x64 ou **ARM64** pour un build ARM64. Les moteurs natifs ONNX et Sherpa nécessitent ces bibliothèques ; les téléchargements de modèles ne les incluent pas. Visual Studio lui-même n'est pas requis pour utiliser l'application.

Outils → Gestionnaire de modèles télécharge les artefacts publiés et vérifie leurs hashes SHA-256 enregistrés. Le traitement utilise les fichiers installés localement. Ouvrez Stockage et vérification dans le Gestionnaire de modèles pour inspecter les avis, réparer une installation ou modifier l'emplacement de stockage.

## Ce que le test empaqueté vérifie {#what-the-packaged-test-checks}

Cas : `transnet-accurate-shots` ; opération : `shot-detection`.

Entrée : Une séquence de 120 images à 30 images par seconde passant du portrait d'astronaute de la NASA à la photographie de chat CC0 à mi-parcours, préparée à la taille de raster du modèle 48 × 27.

Les limites de plan dérivées du modèle doivent être non vides, ordonnées et à l'intérieur de la plage de frames source fournie.

Le package nightly-with-tests télécharge les véritables artefacts de modèle et demande une inférence via le runtime empaqueté. Un modèle requis manquant du catalogue échoue dans son cas. Les moteurs natifs manquants échouent sur les plateformes prises en charge par le catalogue. Ces contrôles coûteux s'exécutent séparément de la suite de navigateurs normale. Une exécution réussie confirme l'exécution de base du modèle et la structure de sortie utilisable ; elle n'établit pas la qualité perceptuelle ou la précision sur votre enregistrement.

## Examinez le résultat {#review-the-result}

- Les fondus, les flashs, les mouvements de caméra et les plans très courts peuvent confondre la détection des limites.
- Le test fournit une coupure visuelle connue et exige des limites de plan dérivées du modèle valides et non vides à l'intérieur des frames source fournies. Il ne remplace pas le détecteur de plans rapides indépendant du modèle.
