## Ce que le test empaqueté vérifie {#what-the-packaged-test-checks}

Cas : `qwen-editorial-proposals` ; opération : `editorial-generation`.

Entrée : Deux candidats aux mises en évidence fixes sur la restauration et la comparaison d'un enregistrement, fournis via le constructeur de plan éditorial de production avec tous les champs de texte demandés.

Le JSON strict doit contenir chaque candidat autorisé exactement une fois et des titres, des accroches et des explications lisibles avec un texte de chapitre valide. Le réviseur de production rejette le contenu dangereux ou étranger.

Le package nightly-with-tests télécharge les véritables artefacts de modèle et demande une inférence via le runtime empaqueté. Un modèle requis manquant du catalogue entraîne l'échec de son cas. Les moteurs natifs manquants échouent sur les plateformes prises en charge par le catalogue. Ces contrôles coûteux s'exécutent séparément de la suite de navigateurs normale. Une exécution réussie confirme l'exécution de base du modèle et la structure de sortie utilisable ; elle n'établit pas la qualité perceptuelle ou la précision sur votre enregistrement.

## Examinez le résultat {#review-the-result}

- La formulation générée peut être trompeuse ou répétitive. Il s'agit d'une proposition basée sur les preuves fournies, et non d'une analyse factuelle vérifiée.
- Le modèle s'exécute localement sur le CPU et nécessite au moins 16 Go de mémoire système totale plus une mémoire libre suffisante. Les courtes requêtes peuvent quand même prendre plusieurs minutes.
- Le test exige un JSON strict, chaque candidat autorisé exactement une fois, et des champs demandés lisibles. Il rejette les commandes, les chemins, la balise, les nouveaux horodatages, les candidats étrangers et les sorties malformées plutôt que de les appliquer.
