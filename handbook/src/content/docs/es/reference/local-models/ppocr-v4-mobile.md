## Propósito y caso de uso {#purpose-and-use-case}

Lea el texto visible de los fotogramas de vídeo muestreados para su revisión e indexación.

## Disponibilidad actual {#current-availability}

Las versiones de escritorio pueden descargar y verificar el motor onnxruntime-node 1.29.0 necesario para macOS arm64, Linux arm64, Linux x64, Windows arm64, Windows x64. Instala este modelo y su entorno de ejecución necesario mediante el Administrador de modelos y ejecuta la tarea localmente. Estos son los destinos de compilación admitidos; consulta el informe de pruebas nocturnas para ver los resultados de un paquete y equipo concretos. La compilación de escritorio no dispone de un motor descargable para macOS x64, aunque los pesos del modelo aparezcan para esa plataforma.

## Utilice este modelo {#use-this-model}

Abra **Framescaper: Herramientas → Búsqueda → Indexar vídeo, o Herramientas → Procesamiento local avanzado → Reconocimiento óptico de caracteres** en una plataforma con el tiempo de ejecución nativo requerido. La asistencia local se ejecuta en el editor de escritorio.

1. Seleccione el vídeo que contiene texto legible en pantalla.
2. Instale PP-OCRv4 móvil a través del Administrador de Modelos. Es un paso opcional de Indexar Vídeo, que también utiliza SigLIP2.
3. Ejecútelo localmente y revise el texto reconocido y sus ubicaciones de fotograma antes de aceptar los resultados.

## Descarga y requisitos {#download-and-requirements}

Identidad del modelo: `ppocr-v4-mobile`, versión **4.0.0**.

Tamaño aproximado de descarga del artefacto del modelo: **15.46 MiB**. El entorno de ejecución necesario se añade a la primera descarga si aún no está instalado. Memoria mínima del sistema: **2 GiB**. Este requisito del catálogo se refiere a la memoria total, no a la memoria libre actual. La inferencia también necesita suficiente memoria libre y la instalación requiere espacio de trabajo; la memoria no garantiza velocidad.

Plataformas publicadas: macOS arm64, macOS x64, Linux arm64, Linux x64, Windows arm64, Windows x64. También se requiere un entorno de ejecución descargable compatible.

En Windows, instala el [Microsoft Visual C++ v14 Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170) compatible más reciente que corresponda a la aplicación de escritorio: **x64** para una compilación x64 o **ARM64** para una ARM64. Los motores nativos ONNX y Sherpa necesitan estas bibliotecas; las descargas del modelo y del entorno de ejecución no las incluyen. No hace falta Visual Studio para usar la aplicación.

Herramientas → Administrador de modelos descarga los artefactos publicados del modelo y el entorno de ejecución necesario durante la primera instalación, y verifica sus resúmenes SHA-256 registrados. El procesamiento usa los archivos instalados localmente. Abre Almacenamiento y verificación en el Administrador de modelos para consultar avisos, reparar una instalación o cambiar la ubicación de almacenamiento.

<details id="what-the-packaged-test-checks">
<summary>Qué comprueba la prueba de escritorio</summary>

Caso: `ppocr-recognized-text`; operación: `optical-character-recognition`.

Entrada: Fotogramas con las palabras de alto contraste «PRUEBA DE MODELO LOCAL», con sincronización de fotogramas de origen explícita.

Las regiones de texto deben contener texto reconocido no vacío, sincronización de fotogramas de origen válida, puntuaciones de confianza finitas y cuadros delimitadores.

El paquete nightly-with-tests descarga los artefactos reales del modelo y los entornos de ejecución verificados antes de la inferencia. Si falta en el catálogo un modelo necesario, su caso falla. La falta de motores nativos provoca fallos en las plataformas admitidas por el catálogo. Estas comprobaciones costosas se ejecutan por separado de la suite normal del navegador. Una ejecución correcta confirma el funcionamiento básico del modelo y una estructura de salida utilizable; no demuestra la calidad perceptiva ni la precisión en tu grabación.

## Revise el resultado {#review-the-result}

- El texto pequeño, borroso, girado, estilizado o parcialmente oculto puede pasar desapercibido o leerse incorrectamente.
- La prueba empaquetada requiere regiones de texto, por lo que el detector, el modelo de orientación y el reconocedor se ejecutan todos. No exige una coincidencia carácter por carácter.
