로컬 어시스턴트는 사운드스케이프 및 프레임스케이프 데스크톱 편집기에서 장치에서 실행됩니다. 미디어를 선택한 다음 메뉴에서 작업을 선택하세요. 대화 상자에는 선택 항목, 작업 설정 및 모델이 설치되었는지 여부가 표시됩니다.

데스크톱 패키지에는 선택 사항인 네이티브 처리 엔진과 모델 가중치가 포함되어 있지 않습니다. 모델 관리자에서 모델을 설치해 필요한 엔진과 가중치를 다운로드한 다음 선택한 미디어에서 작업을 실행하세요. 첫 설치에는 네트워크 연결이 필요하고 이후 처리는 로컬에서 실행됩니다. 지원 플랫폼, 메뉴 항목, 요구 사항은 각 모델 가이드를 참조하세요.

자세한 내용은 [개별 모델 가이드](/reference/local-models/).

## 작업 찾기 {#find-a-task}

| 메뉴 | 작업 |
| --- | --- |
| 효과 → 노이즈 제거 및 수리 | 대화 강화, 잔향 감소, 필러 및 침묵 정리 |
| 효과 → 소스 분리 | 대화/음악/효과 분리 |
| 분석 → 음성 | 전사 및 자막, 화자 식별, 반응 표시 |
| 분석 → 음악 | 비트 및 템포 감지 |
| 분석 → 비디오 | 컷 표시 |
| 효과 → 비디오 효과 | 재구성 |
| 편집 | 하이라이트 만들기 |
| 생성 | 편집 텍스트 생성 |
| 도구 → 검색 | 인덱스 검색, 전사 인덱스, 비디오 인덱스 |

비디오 작업은 프레임스케이퍼에 속합니다. 사용 가능한 명령은 데스크톱 실행 시간과 제품 기능에 따라 다릅니다. 사운드스케이퍼의 알파벳 효과 메뉴 옵션은 또한 로컬 처리 효과를 이름으로 정렬합니다.

**로컬로 실행**을 선택하여 처리를 시작하고 로컬 동의 프롬프트에 응답하세요. 처리가 진행되는 동안 취소할 수 있습니다. **결과 검토**를 선택하고 원하는 결과를 선택한 다음 **선택 적용**을 선택하세요. 수락된 프로젝트 편집은 취소할 수 있습니다. 작업을 닫는 것은 제안을 적용하지 않습니다.

**도구 → 고급 로컬 처리**는 개별 작업 및 모델 선택기를 유지합니다. 작업 대화 상자의 기술 세부 정보는 필요한 경우 기본 단계 및 정확한 설정을 표시합니다.

## 모델 관리 {#manage-models}

**도구 → 모델 관리자**를 열거나 작업 내 **모델 관리**를 사용하세요. 작업 링크는 호환 가능한 모델 ID로 목록을 필터링하고 **모든 모델 표시**는 해당 제한을 해제합니다. 이름 또는 작업으로 검색하고 설치 상태별로 필터링하세요.

모델은 명시적으로 설치하세요. 첫 설치 시 모델에 필요한 누락된 공유 네이티브 런타임도 다운로드합니다. 다운로드 진행률이 표시되며 취소할 수 있습니다. 작업으로 돌아가면 설정은 유지되고 모델 사용 가능 상태가 새로 고쳐지지만 처리가 시작되지는 않습니다. 복구, 정리, 저장소 이동, 라이선스 안내, 폴더에서 오프라인 설치를 하려면 **저장소 및 확인**을 펼치세요. 오프라인 파일로 설치한 모델도 처음 사용하기 전에 해당 런타임이 필요합니다.

게시된 각 모델의 목적, 메뉴 항목, 다운로드 크기, 요구 사항, 제한 사항 및 나이트리-위드-테스트 데스크톱 패키지에 의해 수행되는 실제 추론 확인을 [개별 모델 가이드](/reference/local-models/)에서 확인하세요.

## 플러그인 및 장치 관리 {#manage-plugins-and-devices}

**효과 → 플러그인 관리자**는 사운드스케이퍼의 오디오 플러그인과 프레임스케이퍼의 오픈FX 플러그인을 나열합니다. 목록을 검색하거나 필터링한 다음 플러그인을 선택하여 버전, 권한 및 복구 제어를 확인하세요. **스캔 및 설정**에는 발견 설정이 포함되어 있습니다. 처리가 비활성화되어도 관리가 계속 가능합니다.

**효과 → 오디오 플러그인**을 통해 오디오 플러그인을 사용하세요. 프레임스케이퍼의 추가/편집 비디오 효과 명령은 **효과 → 비디오 효과** 아래에 남아 있습니다.

**편집 → 환경설정 → 오디오 설정**을 열어 네이티브 오디오 장치 및 보조 제어를 확인하세요. **미디어**에는 네이티브 미디어 설정이 포함되어 있고 **효과**는 플러그인 관리자로 연결되고 플러그인 발견 스위치를 포함합니다. 플러그인 권한 및 격리 복구는 여전히 명시적인 동작을 필요로 합니다.
