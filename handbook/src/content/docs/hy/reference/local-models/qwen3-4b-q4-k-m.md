## Ներկայիս հասանելիություն {#current-availability}

Desktop build-երը փաթեթավորում են անհրաժեշտ llama-cpp b10509 շարժիչը macOS arm64, Linux x64, Linux arm64, Windows x64 և Windows arm64 համար։ Տեղադրեք այս մոդելի քաշերը Model Manager-ի միջոցով, ապա կատարեք նրա խնդիրը տեղային։ Այս օգտագործվող build նպատակներն են։ Խորհրդատվություն օրական փորձարկման հաշվետվության մեջ կոնկրետ փաթեթի և մեքենայի համար։

## Օգտագործեք այս մոդելը {#use-this-model}

Բացեք **Framescaper: Tools → Advanced Local Processing → Editorial generation** պլատֆորմի վրա, որն ունի անհրաժեշտ native runtime։ Տեղային օգնությունը կատարվում է desktop editor-ում։

1. Պատրաստեք և ստուգեք ձեր ընտրված մեդիայից հայտնի թեկնածուները։
2. Տեղադրեք Qwen-ը Model Manager-ի միջոցով և ընտրեք editorial generation-ը։
3. Ստուգեք յուրաքանչյուր տեքստային առաջարկը ընդունելուց առաջ։ Միայն լիցենզավորված թեկնածուների նույնականացումները և խնդրված տեքստային դաշտերն են ընդունելի։

## Փաթեթավորված փորձարկումը ստուգում է {#what-the-packaged-test-checks}

Գործընթաց՝ `qwen-editorial-proposals`; գործողություն՝ `editorial-generation`։

Մուտք՝ Երկու ֆիքսված հայտնի թեկնածուներ՝ վերականգնման և համեմատության մասին, մատակարարված production editorial-plan builder-ի միջոցով՝ բոլոր տեքստային դաշտերը խնդրված։

Ճիշտ JSON-ը պետք է պարունակի յուրաքանչյուր լիցենզավորված թեկնածուին ճիշտ մեկ անգամ և կարդալի վերնագրեր, հրավերներ և բացատրություններ՝ վավեր գլխային տեքստով։ Production reviewer-ը մերժում է անվտանգ կամ օտար բովանդակությունը։

Nightly-with-tests փաթեթը ներբեռնում է իրական մոդելային արտեֆակտներ և խնդրում է ինֆերենցիա փաթեթավորված runtime-ի միջոցով։ Կատալոգից բացակայող անհրաժեշտ մոդելը ձախողում է իր գործընթացը։ Բացակայող native շարժիչները ձախողվում են կատալոգ-օգտագործված պլատֆորմների վրա։ Այս թանկարժեք ստուգումները կատարվում են առանձին սովորական browser suite-ից։ Անցնող գործընթացը հաստատում է մոդելի հիմնական կատարումը և օգտագործելի արտաքին կառուցվածքը, բայց չի հաստատում ընկալողական որակը կամ ճշգրտությունը ձեր ձայնագրության վրա։
