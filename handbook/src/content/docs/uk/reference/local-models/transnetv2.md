## Призначення та використання {#purpose-and-use-case}

Знаходьте переходи між планами відео за допомогою точнішої локальної моделі.

## Поточна доступність {#current-availability}

Настільні збірки можуть завантажити й перевірити потрібний рушій onnxruntime-node 1.29.0 для платформ macOS arm64, Linux x64, Linux arm64, Windows x64, Windows arm64. Установіть цю модель і потрібне середовище виконання через Менеджер моделей, а потім запустіть завдання локально. Це підтримувані цілі збірки; результати для конкретного пакета й пристрою дивіться у звіті нічного тестування.

## Використання моделі {#use-this-model}

На платформі з потрібним власним середовищем виконання відкрийте **Framescaper: Tools → Advanced Local Processing → Shot detection**. Локальна допомога працює в настільному редакторі.

1. Виберіть відео у Framescaper.
2. Установіть TransNetV2 через Model Manager і виберіть визначення планів за моделлю.
3. Перевірте запропоновані межі планів перед додаванням анотацій або плануванням редагування.

## Завантаження та вимоги {#download-and-requirements}

Ідентифікатор моделі: `transnetv2`, версія **1.0.0**.

Приблизний розмір завантаження артефакту моделі: **29.81 MiB**. Потрібне середовище виконання додається до першого завантаження, якщо його ще не встановлено. Мінімальний обсяг системної пам’яті: **2 GiB**. Вимога каталогу стосується загальної пам’яті, а не вільної пам’яті зараз. Для виведення також потрібна вільна пам’ять, а для встановлення — робочий простір; пам’ять не гарантує швидкість.

Опубліковані платформи: macOS arm64, Linux x64, Linux arm64, Windows x64, Windows arm64. Також потрібне відповідне середовище виконання, доступне для завантаження.

У Windows установіть останній підтримуваний [Microsoft Visual C++ v14 Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170), сумісний із настільною програмою: **x64** для збірки x64 або **ARM64** для збірки ARM64. Нативним рушіям ONNX і Sherpa потрібні ці бібліотеки; завантаження моделі та середовища виконання їх не містять. Для використання програми Visual Studio не потрібна.

Інструменти → Менеджер моделей під час першого встановлення завантажує опубліковані артефакти моделі й потрібне середовище виконання та перевіряє записані дайджести SHA-256. Обробка використовує локально встановлені файли. Відкрийте Сховище та перевірка в Менеджері моделей, щоб переглянути сповіщення, відновити встановлення або змінити місце зберігання.

Випадок: `transnet-accurate-shots`; операція: `shot-detection`.

Вхідні дані: послідовність із 120 кадрів зі швидкістю 30 кадрів за секунду, де посередині портрет астронавтки NASA змінюється на світлину кішки CC0; підготовлена в розмірі 48 × 27 пікселів, потрібному моделі.

Визначені моделлю межі планів мають бути непорожніми, упорядкованими та лежати в заданому діапазоні вихідних кадрів.

Пакет nightly-with-tests завантажує справжні артефакти моделі й перевірені середовища виконання перед виведенням. Якщо в каталозі немає потрібної моделі, її тест завершується помилкою. Відсутність нативних рушіїв призводить до помилок на платформах, підтримуваних каталогом. Ці ресурсомісткі перевірки виконуються окремо від звичайного набору браузерних тестів. Успішний запуск підтверджує базову роботу моделі й придатну структуру виходу, але не доводить якість сприйняття чи точність на вашому записі.

## Перевірка результату {#review-the-result}

- Згасання, спалахи, рух камери та дуже короткі плани можуть ускладнити визначення меж.
- Тест подає відому візуальну склейку й вимагає правильні непорожні межі від моделі в межах вихідних кадрів. Окремий швидкий детектор без моделі не використовується як підміна.
