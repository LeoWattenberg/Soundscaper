# Local model conversion evidence

These records retain actual CPU conversions and source-framework comparisons for
PANNs Cnn10, both Beat This checkpoints, TransNetV2, TIGER-DnR, and Dereverb Room.
The runs used the committed Python dependency lock on Linux x64. They establish
conversion parity on these fixtures; they do not claim inference was tested on
every desktop platform.

Each candidate directory contains the converted artifact identities, original
source input identities, exact command arguments and environment, separate command
output streams, comparison results, and the raw framework outputs used to compute
those comparisons. Float arrays use little-endian Float32 (`.f32le`); indexes use
little-endian signed 64-bit integers (`.i64le`). Parity inputs are the owned,
deterministic fixtures generated by
`scripts/models/milestone-7-parity-fixtures.mjs`. No upstream source archives,
checkpoints, or converted neural networks are committed in this directory.

`production-worker-smoke.json` records additional Linux x64 runs through the
production TypeScript worker and ONNX Runtime 1.29.0, using the nightly test's
generated fixtures and licensed speech and images. These records cover the production input
preprocessing and output handling separately from source-framework parity. They
are direct worker probes; the nightly suite also exercises packaged Electron.

The source revisions, upstream checksums, conversion recipes, and converted file
hashes are in `config/milestone-7-model-supply-candidates.json`. SHA-256 readbacks of
archives and source files, the exact commands, and canonical comparison evidence
digests are bound by `config/milestone-7-model-conversion-execution.json` and
`config/milestone-7-model-parity-fixtures.json`. A comparison digest is the SHA-256
of its canonical JSON value, not its formatted file bytes.

To replay, create a fresh workspace, install the frozen environment from
`scripts/models/milestone-7-conversion-tool/uv.lock`, acquire the pinned source
archive and checkpoint files, and verify every input against
`source-input-manifest.json`. Generate the pinned fixture as `parity-fixture.bin`
and copy the lock as `uv.lock`. Execute the candidate's `convert` and `parity`
commands from the execution register with its seven specified environment
variables. Select the installed environment's Python interpreter. Downloads occur
before conversion; the conversion and parity commands require neither a network
nor a GPU. The tool authenticates the source closure before importing model code
and never overwrites converted artifacts or comparison outputs.

The PANNs checkpoint was acquired from the same pinned
[Zenodo record's file endpoint](https://zenodo.org/records/3987831/files/Cnn10_mAP%3D0.380.pth?download=1)
when its API content endpoint refused the request. Its upstream MD5 and retained
SHA-256 readback were both verified before conversion.

The Beat This graphs accept one batch and a variable number of spectrogram frames.
TransNetV2 accepts one fixed 100-frame batch. These dimensions match the desktop
adapters and avoid freezing an incorrectly advertised batch size while tracing
the upstream code. TransNetV2 uses its pinned upstream TensorFlow-to-PyTorch
weight converter and retains independent TensorFlow, PyTorch, and ONNX comparisons.
Both Beat This checkpoints retain separate logits and point comparisons.

`conversion-evidence.json` also indexes the large files that remain outside this
repository. After placing those files at its relative paths in a complete evidence
workspace, validate the entire closure with:

```sh
node scripts/models/verify-milestone-7-conversion-execution.mjs \
  --bundle evidence/milestone-7-model-conversion/panns-cnn10/conversion-evidence.json \
  --root /absolute/path/to/complete/panns-workspace
```

The normal tests validate the committed records, command logs, and raw comparison
outputs without running or downloading models. Actual inference remains in the
separate nightly Electron model suite.
