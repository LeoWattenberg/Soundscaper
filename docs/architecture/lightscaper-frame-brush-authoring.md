# Frame image brush authoring

Frame's selected static image offers **Brush mask…** in the existing Effect
menu. The dialog creates a new alpha mask or re-edits an installed brush mask;
painting, erasing, stroke undo and redo stay in its local draft. Applying the
dialog installs an immutable resource and then sends the resulting develop
recipe through Frame's existing selected-image command and history owner.
The workspace dispatcher admits the brush menu kind, and the dialog backdrop
owns pointer input within the effects overlay so canvas gestures reach the
brush editor.

## Shared authoring and product custody

`ImageBrushMaskAuthoringV1` owns bounded replay, authenticated predecessor
alpha, local stroke history, scoped display, installation and joined
retirement. The Photo facade retains its catalog-specific acknowledgement
validation. The Frame adapter validates the actual selected project identity.
Neither adapter changes the other product's storage or publication identity.

The selected Frame session captures the existing media reader, metadata reader
and transactional writer with their real receivers. The brush capability uses
that same native store and the session's exclusive operation admission; it
creates no second project connection or writer lease. Each resource operation
authenticates the retained project's complete LUT and brush closure, including
disabled effects and unused declarations.

Installing a resource acknowledges native body storage independently of the
recipe edit. Reusing an existing key verifies its metadata and authenticates
its body. A new body is published through the captured owned writer. An
acknowledged body remains immutable if cancellation, a stale selection or a
later recipe publication failure prevents Apply. Frame's existing resource
retention and garbage collection own its subsequent lifetime.

## Unpublished preview

Painting borrows replay alpha and a bounded encoded brush body. The named
brush-draft renderer captures the complete recipe, reference, body and optional
mask/effect selection before yielding. Its private body override serves only
the exact declaration in that recipe; other retained resources still come
from authenticated native storage.

The preview borrows the real canonical Original, uses the shared develop
kernel and displays natural developed output after repairs and geometry.
Color and grayscale coverage are optional, effect-aligned presentation modes.
They start off and remain outside the stored recipe. A stroke creates no
native media body, history entry or persistent source identity.

The installed-only draft capability remains a separate, closed interface.
The selected session shares one admission slot between Original borrowing,
installed draft rendering, temporary brush rendering, resource reading and
installation. Its byte admission includes authoring replay and encoded scopes
alongside native Original, resource authentication, developed pixels, coverage
and canvas allocations, within the existing 512 MiB bound.

## Apply and retirement

Apply waits for authoring work, validates a genuine resource acknowledgement
and uses the existing selected-image source command. Re-editing preserves the
mask's scalar identity, graph, bindings and enabled flags. Its predecessor
resource stays immutable, so global undo and redo can recover either recipe.

Close remains available when native currentness is lost or preview work
fails. Presentation seals callbacks and joins registered children before the
selected native session releases its preview suspension. Borrowed alpha,
encoded brush bytes, developed pixels, coverage and canvas planes retire
inside their owning scopes. Cleanup preserves independent failures and never
discards an acknowledged body merely because the dialog closes.

This browser and UI change uses the existing assistance runtime closure and
does not require a manual **Update AI assets** run.
