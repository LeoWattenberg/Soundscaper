# Current native-depth Develop proxies

The existing Develop Settings menu selects Fit-screen proxy by default and
offers Full resolution (100%). Current proxy mode now samples the authenticated
Original before evaluating adjustments. It does not render every full-resolution
stage and then shrink the canvas. Full inspection, export and editable handoff
retain the full-resolution render of record.

The selected Original reader still lends the complete, oriented native frame
under its Photo revision and retained byte/hash binding. Camera embedded previews
and disposable culling caches never supply Develop. RAW decoding itself remains
full resolution; this change bounds subsequent adjustment work.

## Sampling and evaluation

Metadata admission first captures the Original descriptor, complete unchanged
recipe, selected mask, resource capabilities, natural proxy stage extents and
working-byte plan. Unsupported profiles, missing resource authority and
impossible declared work refuse before source pixels are consulted.

A private source owner fits the Original into 2048 by 2048 using the established
rounded aspect convention and top-left nearest sampling. It copies selected
samples synchronously before its first yield. UNORM16 remains UNORM16 and
Float32 remains Float32 with the same primaries and transfer; signed/HDR values,
adjacent words, negative zero and subnormals never pass through RGBA8. Encoded
sRGB byte Originals keep their byte execution path. The proxy has dedicated,
fixed backing and preserves selected hidden RGB and straight alpha.

The unchanged recipe then runs on that native proxy grid through the existing
ordered repair, geometry, color, spatial, LUT and local-mask kernels. Normalized
crop, perspective, donor, spot and mask coordinates remain normalized. Fixed
neighborhood taps, pixel feather radii, seeded grain and the Heal solver operate
on the proxy lattice. Spatial and repair previews can therefore differ from
full inspection, as the existing proxy policy permits. There is no persisted
parameter rescaling, process upgrade, history edit or alternate saved recipe.
Natural geometry uses the reduced dimensions and its existing rounding rules;
its extent need not equal a rounded scaling of the full natural output.

Proxy source bounds are 2048 pixels per side and 4,194,304 pixels. Natural
stages may grow within the separate 4096-side/8,388,608-pixel render profile.
Word/float processing charges the actual sample depth. Byte metadata planning
uses conservative Float32 costs, while execution keeps the permanent byte
renderer. The permanent V3 byte-derivative API is unchanged.

## Ownership and publication

The downstream plan includes the native proxy input once. The source owner
adds the entire intrinsic full-Original backing once, including padding, under
a 768-MiB processing bound. Declared lower bounds refuse before pixel admission;
actual backing size is checked before allocation. Masks, complete brush
declarations, LUT bodies/parser reserves, stage replacements and display work
retain their existing charges. This phase bound is not a whole-application heap
claim or a bound for decoder/browser-native storage.

GPU preference admits its complete preferred phase beside the full physical
Original backing: native proxy input, private Float32 capture, two RGBA32F
targets, Float32 readback and the existing full/fitted presentation allowance.
Active extended color passes add a 4096-byte uniform-staging reserve; streamed
CPU conformance checking allocates no expected-result image plane. Capability
probing has a separate fixed reserve. If that phase cannot fit but
the entire CPU phase can, the same admitted source and one proxy capture select
CPU before GL allocation. If neither fits, the request refuses. No fallback
reopens the Original.

Native promotion starts at the fitted proxy extent; each adjustment uses its
admitted natural proxy stage extent. No full-Original Float32 capture is
allocated merely to construct a smaller proxy. Each scoped
proxy and pipeline backing is physically wiped after its joined consumer.
Cancellation joins held consumers; opaque operation errors and independent
retirement failures remain observable together.

Before histograms use the fitted Before plane in proxy mode; After histograms
describe the evaluated natural proxy output. Full mode retains full-image
histograms. Display extents remain display metadata. Resolution changes and
Close use the existing serial presentation owner and authenticated Original
lifetime. Ready publication follows both decoder retirement and a final Photo
revision check; a revision change during retirement clears painted targets
instead of publishing the stale result.
