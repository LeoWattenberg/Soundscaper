# Photo catalog archive V5

The named V5 codec carries complete admitted Photo1/2 documents, schema1/2
Develop preset rows and the immutable `.cube` bodies reachable from those
documents. It leaves the named V1–4 codecs strict and unchanged. This packet
provides codec, backup and private restore owners; current Session/runtime and
menu adoption is a separate integration step.

`createPhotoCubeLutReachabilityV1` admits each complete Photo or preset before
walking every version, history entry including redo, named snapshot and full
or partial preset. Disabled effects retain custody references. Only detached
scalar references survive enumeration. Identical SHA identities must also
agree on byte length and cube geometry. This ledger proves reachability rather
than body authenticity or physical storage inventory.

The V5 project declares unique `assets/luts/<sha256>.cube` entries. The Photo-only
asset kind is `photo-cube-lut`; its encoding is `lightscaper-cube-utf8-v1`.
Photo packs use `lightscaper-photo-pack-v2` and the unchanged bounded binary
record structure with complete Photo1/2 admission. Preset packs declare the
exact delivered row schema, revision and count. Physical absence and positive
empty rows are distinct; reading an old row does not promote it.

The combined original/stack/saved/preset packs and LUT resources remain capped
at 4,094, within the existing 4,096 ZIP entries. Project JSON remains bounded
at 4 MiB, manifest JSON at 32 MiB and expanded data at 64 GiB. The explicitly
named V5 output estimate accounts for the longer LUT entry names; all prior
estimates and admissions remain unchanged. One LUT raw body is bounded at
16 MiB and is authenticated through the existing V27 parser/reference owner.

Backup captures physical preset presence and complete normalized row contents
under the existing selected writer. Bounded summary pages lead to complete
owning Photo admission and retained original verification. LUT method and
receiver identities are captured before awaits. Every unique raw body is
authenticated serially before emission, then reauthenticated before destination
Close. Complete one-shot source verification follows that final resource pass. Scoped
raw byte copies are wiped after source and consumer settlement; borrowed parsed
numeric arrays retain their existing V27 lifetime and cannot be zeroed.

Private restore first authenticates the project, manifest and complete records.
Exact LUT reference and body proof precedes delivery to the captured candidate
writer. Named V1–4 input remains compatible only after its own codec admission;
legacy formats carry no LUT declarations. Archive-reader retirement settles
before candidate readiness or pointer publication.

The mixed catalog candidate remains a fresh DB5 namespace and derives the
existing summaries, memberships and Query1/2 projections only after full
Photo1/2 admission. The fresh media candidate uses the existing DB2 `analysis`
store for immutable `photo-cube-lut-body` records. It introduces no schema
migration and preserves original custody keys, counts and byte receipts.

Before original promotion, and again before the final native readiness ACK,
the candidate compares every reachable reference with the complete declared
inventory, authenticates each native body point read and pages only the exact
`lut-sha256:*` namespace. Other computed-analysis namespaces remain valid.
Malformed row metadata also wipes the already-owned native body clone. The
final joined media transaction includes `analysis` alongside the unchanged
settings, asset, chunk and original-root stores.

Close and rollback install their cached joins before cancellation callbacks.
Admission seals synchronously, held operations and native completion settle,
and one deletion retains the fresh-name barrier through its ACK. The existing
restore journal, namespace leases, permanent publication history and pointer
CAS remain the publication authority. Post-pointer ACK cancellation cannot
turn an installed library into rollback; uncertain publication is reconciled
against those existing authorities.

Focused strict tests cover real ZIP body corruption, row/schema/digest drift,
complete mixed native candidate audits, opaque cancellation, held completion,
abort reentry and publication reconciliation. Actual current Session reopen,
second backup, product builds and native browser qualification are subsequent
integration evidence, rather than claims established by this codec packet.
