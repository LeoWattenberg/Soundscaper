## Shared execution and fallback

`image-develop-gpu-current-v1.ts` admits the entire Current recipe, selected
mask overlay, resource authorities, geometry and processing limits before source
samples. The broker uses the existing native CPU engine as its whole-recipe
fallback. An unfinished stage never disappears from a GPU result.

Current local masks, selected overlays and Original-space Clone/Heal enter
the native GPU path alongside color, LUT, geometry, optics and spatial stages.
The existing Repair spots and Preview rendering menus remain the opt-in entry
points; no additional always-visible controls or saved renderer setting is added.
Encoded byte sources also retain their existing CPU process and
per-stage byte quantization. They are not implicitly promoted into the native
Float32 process to obtain GPU execution.

Mask checkpoints retain every authored position, including disabled or neutral
adjustments selected for observation. Graphs sample the actual incoming native
stage. A bound candidate preserves that incoming texture, writes its adjustment
to a second bank and blends into a distinct third bank. Authenticated brush
alpha is the only uploaded coverage; gradients, shapes, paths, ranges, boolean
operations and feathering execute through native integer textures. Every
declared brush authenticates before GL, including unused and disabled inputs.

Selected coverage projects through the exact ordered geometry and lens suffix.
Every suffix draw stores R8UI bytes, so the next warp samples the previous
rounded result. Projection textures and integer readback scratch retire before
proof reads the retained GPU-derived host plane. Tagged byte receipts verify
every executed checkpoint and the selected overlay against the unchanged CPU
process before the final native-image comparison. A separate private stripe
reader serves proof before the one external presentation borrow; neither
reader can reopen the retired owner. Brush, LUT and proof scopes retire before
external delivery; the host overlay remains live until its consumer joins.

The complete private phase ledger replaces conservative component sums only
for the exact admitted checkpoint/context/overlay owners. It charges padded

independent native and canonical stripes, authenticated resources and final
presentation. GPU graph and CPU graph storage run in separate phases. The
2048×2048 native-word radius-64 feather witness produces accepted GPU output on
both locally tested engines within the unchanged 64 MiB mask and 768 MiB total
limits. A fitting direct CPU route is chosen before GPU capture when padding
makes an attempted GPU route too large.

Overlay byte proof is exact. A 4×4 gradient rotated 45 degrees exposes a

The high broker also qualifies real native q128 blend cancellation: a readback

## Native samples and capability

The shared host accepts native linear sRGB/BT.709 UNORM16 or Float32 frames.
UNORM16 normalizes by 65535 into a privately owned Float32 snapshot. Float32
input retains signed/HDR samples. Source metadata and samples are captured
before the first asynchronous context-loading boundary; later caller mutation
cannot replace the admitted frame. Proxy mode first samples the existing
same-format native proxy grid, then evaluates the unchanged recipe on that grid.

The optional context owner uses two RGBA32F textures for ordinary unmasked
recipes and three for masked candidates or a repair prefix, with nearest
sampling and integer `texelFetch`. Each authored operation writes a Float32 stage. White
balance, tone and wheels operate in native linear RGB. Tone uses the stable
affine contrast form and clamps only its regional smooth weights; wheels use
signed lift, gain and gamma. Chroma, black-and-white, HSL and curves use
continuous sign-symmetric extended-sRGB coordinates and return to linear RGB
without a byte lookup or encoded working plane. Curves share the CPU's authored
knots and parametric Q16 gain definition; master and channel compose before the
stage store. Distinct curve knots that collapse in Float32 uniforms or nonfinite
uniform slopes select CPU. Color/LUT stages copy straight alpha exactly;
resampling must match the CPU's computed output alpha exactly. Hidden RGB retains
the CPU process's semantics. Final display, proofing and histogram generation
retain their existing owners.

Extension names alone do not grant support. A native upload/render/readback
probe checks signed/HDR values, negative zero, small normal samples, subnormal
copy/arithmetic and alpha. The admitted pass identities retain a private link
to the existing CPU operation, allowing numeric admission to consult that
normative operation without duplicating its formulas.

For pointwise color/LUT recipes, a bounded streaming check evaluates the existing
normative CPU scalar and rounds once per authored effect. Alpha, signed zeros,
expected RGB magnitudes below `2^-60` and final unchanged native components must
match exactly. Other finite normal results permit at most eight Float32 ULPs;
no absolute epsilon can erase a signal. A mismatch retires GPU resources before
the complete CPU fallback. The check allocates no expected-result image plane.
Geometry, optics and spatial recipes instead use the whole-plane reference
described below. Both checks evaluate CPU work, so this packet makes no speed claim.

Some tested drivers flush subnormal arithmetic. Affected source or intermediate
profiles take the CPU path. Nonlinear near-zero and ill-conditioned cancellation
profiles also fall back conservatively. The contrast-pivot witness at
Float32(.135) and contrast 100 retains a nonzero CPU result of approximately
2.1457672e-8; returning GPU zero is not accepted as equivalent. Float32 rounding
of derived identity-curve knots can also drift an otherwise unchanged native
channel. Even a two-ULP difference then selects CPU: the eight-ULP allowance
does not apply to an unchanged component. Readback is never patched with CPU
samples to manufacture conformance. This result contract is not a universal
shader-accuracy or capability claim over every finite control and sample.

## Authenticated cube LUTs

The Original snapshot finishes before the first asynchronous resource read.
Closed LUT references bind their SHA-256, byte length, lattice size and input
domain. Every unique body passes the existing parser and those complete identity
checks before GL opens. Reads are sequential, with no nested repository borrows;
the source method and receiver are pinned before awaits. Repeated authored
references share one private table without changing effect order.

Each authenticated table is copied into private Float64 storage for the
normative CPU sampler. The Float32 RGBA upload bank is separate and cannot
become that oracle: rounding two lattice endpoints can erase a real interpolated
signal. The shader uses eight explicit nearest texel reads and the CPU's
red-fastest, B→G→R difference-form interpolation. Only declared input-domain
coordinates clamp. Signed/HDR output remains unclipped, each authored stage
stores Float32, and straight alpha remains exact. Float32-collapsed domains or
nonfinite uploads select whole CPU processing after body authentication.
The texture operations follow the [WebGL2 specification](https://registry.khronos.org/webgl/specs/2.0/)
and its [float render-target extension](https://registry.khronos.org/webgl/extensions/EXT_color_buffer_float/).

One reusable RGBA32F 3D texture and one host upload bank use the largest selected
lattice; smaller passes read only their declared lattice extent. The LUT shader
variant requires 143 fragment-uniform vectors. The existing eight-ULP and exact
component guards apply unchanged to the private Double oracle. Numerical or
capability refusal retires the resource and GL scopes before whole CPU fallback.
That CPU phase can read LUT bytes again through the same pinned source method
and complete SHA-bound reference; the Original is never reopened. Authentication,
opaque operation, cancellation and cleanup failures remain fatal and never
trigger replay.

## Natural-extent geometry

Legacy top-level geometry runs first; authored
crop, rotation, flips and perspective stay at their actual effect positions.
Complete private pass identities and the descriptor chain are admitted before
pixels. The maximum is 257 passes: one legacy geometry followed by up to 256
authored effects. Each stage retains its Float32 store, natural output descriptor
and viewport. Two ping-pong textures resize for the next admitted extent, clearing
their prior application-visible storage before replacement. Readback uses the
final descriptor, which may differ from the Original in both dimensions.

Integer-pixel crops and quarter turns without perspective have an exact integer
inverse mapping. That shader path avoids rounded normalized-coordinate drift.
It still performs geometry: alpha zero clears every component to positive zero,
and visible RGB zeros canonicalize to positive zero as in the CPU accumulator.
An explicitly authored identity geometry is therefore not an omitted no-op.

Generic geometry uses output pixel centers, the captured affine aperture map
and projective division. Four explicit integer texel reads clamp to the crop's
inclusive pixel bounds. The rectangular crop extends its edge samples; outside
the rotated aperture is transparent. Filtering accumulates premultiplied linear
RGB and alpha, then divides RGB by the unrounded accumulated alpha. Only output
alpha clamps to its unit range; alpha rounding to zero clears RGBA. Signed/HDR
RGB has no output clamp or encoded intermediate.

A sequential whole-plane CPU reference uses the existing geometry writer and
native color/LUT operations, storing Float32 after every authored stage. It owns
at most two maximum-extent reference planes and retires predecessors immediately;
there is no recursive neighborhood sampler or provenance image. Output alpha
must match the CPU result exactly. Geometry-only integer-permutation chains
require exact RGBA. Mixed stacks retain the zero, tiny and unchanged-component
guards and the existing eight-ULP allowance for other normal RGB. Integer
ancestry uses the private exact inverse maps rather than a same-index source
assumption after a crop or rotation. The reference's finite-source validation,
stage evaluation, comparison and reverse-ancestry work yield to cancellation;
intrinsic source capture and bulk plane copies remain synchronous.

The existing CPU mapper can retain tiny neighbor support at nominal integer
centers through Double-coordinate roundoff. If that survives Float32 storage,
the exact integer GPU fetch must select whole CPU processing. Float32 projective
mapping and aperture-boundary differences can also refuse numerical admission.
Neither the CPU model nor the precision budget changes to force GPU acceptance.
Private Double LUT tables stay alive through the complete reference comparison,
then retire before final consumer delivery. Readback is never repaired with CPU
samples. These checks preserve the same Original, recipe and resource authority.

## Native manual optics

Four private prepared kinds bind each admitted incoming descriptor to the
existing CPU plan: 10 lens distortion, 11 chromatic
aberration, 12 defringe and 13 optical vignette. Each keeps that same aperture and
extent; preceding geometry changes the aperture used by later optics. Effects
stay in authored order and store Float32 after each stage. Captured uniforms
retain separate raw activity flags and enabled state, so rounding a coefficient
to zero never silently turns an active filter into a source copy.

Lens distortion and CA use signed radial displacement, with integer offsets and
directly retained fractional magnitudes. This avoids losing a small shift when
adding it to an absolute pixel coordinate. Their four taps use per-tap transparent
zero-extension outside the incoming image, unlike geometry's crop-edge clamp.
Lens filters premultiplied linear RGBA, divides by unrounded alpha and clears
RGBA when output alpha rounds to zero. Only a raw-neutral or disabled lens copies
the source unchanged. An active zero-derived coefficient can still clear hidden
RGB through filtering.

CA reconstructs each active R/B channel using its own supported, unrounded alpha
sum. Green, reference alpha and raw-zero-controlled channels retain exact native
bits. Reconstructed channels can contain supported neighbor color even at a
reference alpha-zero pixel. Tiny inward shifts can create diagonal support below
`1e-48` that Double reconstruction normalizes to a visible value; Float32 loss of
that support must select the exact whole-CPU result, never a coefficient floor.

Defringe evaluates continuous odd-sRGB values on the immutable incoming plane.
Its clamped 3×3 neighborhood excludes the logical center but retains clamped
aliases, and only positive-alpha neighbors contribute. Alpha-weighted opponent
differences are accumulated before normalization, preserving flat neutrality.
Alpha-zero centers, zero correction weight and individually unchanged encoded
channels bypass conversion and retain source bits. Output alpha is copied;
changed RGB returns to linear without clipping. Optical vignette instead applies
a direct positive linear `exp2` gain in the incoming aperture. Its alpha-zero,
gain-one and zero-component branches retain exact bits; native overflow refuses.

The same two-plane CPU reference executes the existing native optics writers,
including lens/CA sampling and defringe neighborhoods. It keeps per-stage Float32
stores and exact normative output alpha. There is no provenance image: active
lens reconstruction invalidates a same-pixel RGB witness; CA invalidates only
its corrected channels, and coupled color/LUT stages and active defringe
propagate that invalidation.
Later operations never invent a unique Original ancestry for reconstructed color.
Finite-source validation and reference work yield to cancellation, and all
reference storage retires before consumer delivery.

Stable displacement removes coordinate cancellation but cannot recover an
authored Double coefficient from one rounded Float32 uniform. The non-dyadic
3×1 inward lens witness retains its one-ULP output-alpha mismatch as a required
numerical refusal with exact CPU output. The qualified positive corpus uses
coefficient `±5/32`, edge displacement `±1/16`, and fractional alpha/transparent
support with exactly representable weights. These are distinct proofs; neither
changes the CPU model, exact-alpha guard, other precision rules or source custody.

unsigned polynomial arithmetic and explicit signed floor division preserve the

protection couple RGB, so any prior CA/resampling invalidation propagates to all

The existing native CPU writer re-evaluates every spatial stage on its actual

capacity or capability refusal retires the attempt before whole CPU fallback;
invalid metadata, cancellation and independent cleanup failures remain errors.
No readback repair, tolerance relaxation or acceleration claim is made.

## Working set and retirement

The Current preview working ceiling remains 768 MiB. Admission charges the full
physical borrowed backing, including padding outside a valid source view.
Native GPU execution overlaps that backing with one Float32 host capture,
two maximum-extent RGBA32F textures (three when required by masks or repairs)
and one final-extent Float32 readback. Geometry, optics, spatial, masks or repair
recipes additionally reserve two maximum-extent CPU reference planes. A repair
prefix retains the same three maximum-extent image banks through proof and
presentation. Its serial GPU halo uses eight RGBA32F banks and one R8UI membership
bank, 129 bytes per halo cell. Those programs and halos complete clearing and
retire before later masks, final readback and CPU replay. The disjoint CPU repair
prefix uses the unchanged 105 bytes per halo cell of Float64/byte scratch plus
4096 bytes, then retires scratch and the replaced oracle plane before authored
replay. No third CPU oracle image or combined GPU-halo/CPU-scratch phase is added.
Color/LUT-only pointwise recipes retain the streamed comparison and allocate no
reference image plane.
Presentation planning also reserves
a full RGBA8 conversion plus a bounded fitted presentation allowance beside the
live native working set. Histogram and display conversions can run sequentially;
this is a conservative reserve, not a claim that both byte planes remain live
together. It charges 4 bytes per output pixel plus 4 bytes per fitted pixel,
with the fitted allowance capped at 4,194,304 pixels.

Any prepared kind greater than 2 conservatively reserves 4096 bytes for bounded
uniform staging. Extended color/LUT execution uses one reusable Float32 bank for
band controls and curve points; the separate spatial program does not require
the 142/143-vector color/LUT uniform capacity. The
pointwise streamed comparison introduces no additional image plane or
pixel-bearing rank scratch. Capability probing retains its separate fixed
reserve.

LUT planning charges the sum of unique Float64 RGB tables, one maximum-size
Float32 RGBA upload bank and one matching 3D texture. A 65³ table costs
6,591,000 oracle bytes and 4,394,000 bytes each for upload and texture storage.
The separate capture phase charges the retained Double prefix including the
current table, a 128-MiB parser/transient reserve, the full 16-MiB admitted
borrowed backing and the reference's raw snapshot byte length. Padding outside
an authenticated source view therefore cannot hide physical source cost. The
ceiling stays 768 MiB; an oversized valid set selects whole CPU before GPU I/O.
These scalar reserves are not an exact JavaScript-engine or driver heap bound.
Existing parser text and frozen numeric scratch are released without a claim
that their physical memory can be wiped. The new mutable Double snapshots and
upload bank have explicit wipe ownership.

GPU and CPU fallback have separate phase plans. Proxy admission chooses once
using the actual physical Original backing before allocating its private proxy.
If GPU preferred cannot fit beside that backing but the complete CPU phase can,
it directly selects CPU. A combination that cannot fit either phase refuses.
No generic RangeError catch reopens the source, and the existing byte, native
frame and Original limits are unchanged. Maximum accepted image dimensions do
not promise that every GPU working set fits.

Bounded numeric scans yield to cancellation. Queued GPU work uses a fence and
zero-timeout polls with task yields before readback; context loss is checked at
execution boundaries. Scoped consumers join before host planes retire. Opaque
primary errors retain their identity, and distinct cleanup failures remain
observable. A delivered consumer is never retried through CPU fallback.

The context owner clears application-visible textures where the context still
accepts commands, deletes its handles, requests context loss when available and
zeros canvas backing dimensions. Captured host samples, probe arrays and readback storage
have physical wipe ownership. Deleting GL resources does not certify erasure
of driver-private GPU memory; a lost context cannot accept overwrite commands.
Private Double tables retire before the final GPU consumer. The GL texture and
host upload bank stay owned through that joined consumer; retirement wipes the
bank and clears every layer of the maximum-size cube before deleting its handle
when the context still accepts commands.
